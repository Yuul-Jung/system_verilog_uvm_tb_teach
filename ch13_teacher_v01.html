00개요 · 바이트 거래와 검증 환경

제4부에서는 실제 인터페이스와 연산 IP를 검증합니다. 첫 대상은 UART(유아트, 비동기 직렬 통신) 에코의 바이트 스트림 전달 회로입니다. BFM(Bus Functional Model, 버스 기능 모델)은 입력 거래를 구동하며 Monitor(모니터, 관찰기)는 모든 샘플 에지를 별도로 감시합니다.

선행 설계 학습안내서: Basys3 소형 NPU 실습(amd_soc_npu) 제1장 UART 계산기, 03절 「서브젝트 1-1 · UART 에코」, uart_echo_controller.v. 이 장은 UART 직렬 수신기나 FIFO가 아닌 조합형 에코 제어기만 검증합니다.

교수용 이론 · 자극이 믿는 수락과 실제 관찰을 분리한다

BFM(Bus Functional Model, 비에프엠, 신호로 거래를 구동하는 모델)이 A를 보냈다고 기록한 것과 실제 샘플에서 A가 수락된 것은 다른 사실입니다. 그래서 입력을 바꾸는 task와 별도로 모든 상승 에지를 보는 모니터를 둡니다. 검사 호출이 빠진 구간이나 예상하지 않은 추가 수락도 관찰하기 위한 구조입니다.

이 장의 프레임은 A·Z·LF 세 바이트의 순서입니다. UART 직렬 선의 시작 비트·8데이터 비트·정지 비트로 이루어진 8N1 물리 프레임은 다음 실제 UART 코어 시험과 구분합니다.

01원본 RTL · 실제 6포트 연결

수신 데이터와 유효 신호는 송신 쪽으로 전달되고, 준비 신호는 반대 방향으로 전달됩니다. 원본은 세 연속 대입문만 가지며 클록·리셋·레지스터가 없습니다.

reference_rtl/uart_echo_controller.v · Verilog
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule

그림 읽기 · TB 클록은 DUT 포트가 아니다

데이터·valid 화살표는 수신에서 송신 방향이고 ready는 반대입니다. 조합 DUT는 둘을 그대로 연결할 뿐 수락 기록을 보관하지 않습니다. tb_clk은 모니터가 거래를 어느 시점에 셀지 정하는 TB의 시간 기준입니다. 따라서 수락3은 모니터의 계약에 따른 집계이며 내부 UART 송신기가 직렬 전송을 완료한 수가 아닙니다.

02Ready/Valid · 전송 수락과 대기

Ready/Valid(레디/밸리드, 준비/유효 신호)는 송신 측이 유효 데이터를 제시하고 수신 측이 받을 수 있을 때 거래를 수락하는 계약입니다. 이 장에서는 TB의 10ns 샘플 클록 상승 에지로 거래를 정의합니다. DUT 자체에서 클록에 따라 저장하거나 수락하는 것은 아닙니다.

validready판정
00 또는 1수락 없음
10대기, 데이터와 valid 유지
11한 바이트 수락
1X 또는 Z확정 수락 아님

데이터와 유효 신호는 하강 에지에서 변경하고 상승 에지에서 관찰합니다. Backpressure(백프레셔, 수신 측의 전송 지연) 중 데이터 유지 책임은 BFM에 있습니다. DUT가 저장하는 것이 아닙니다. 연속 전송에서는 valid가 계속 1이어도 매 상승 에지에 새 바이트를 수락할 수 있습니다. 이 예제는 바이트 사이에 유휴 구간을 둡니다.

판서 · 대기 표본 다음에 무엇을 유지해야 하는가

35ns에 valid1·ready0이면 Z는 아직 수락되지 않았습니다. 다음45ns에도 Z·valid1을 유지하고, ready가1로 돌아온55ns에도 같은 Z를 제시해야 합니다. 모니터는 이전 샘플이 STALL이면 held_data를 기준으로 다음 샘플의 data·valid를 확인합니다. 수락 직전까지 값이 바뀌지 않아야 대기 중인 바이트를 잃지 않습니다.

이번 BFM은 data·valid와 함께 상대 수신 준비를 나타내는 ready도 시험 목적으로 제어합니다. 실제 DUT가 내부 버퍼로 backpressure를 흡수하는 구조는 아닙니다. 정상0/1 제어에서 동작하는 유지 검사와 의도적인 X/Z 준비 사례의 범위를 나누어 읽습니다.

03거래 시퀀스와 예상 샘플

문자 A(41), Z(5A), 줄바꿈 LF(0A)의 세 바이트를 순차 전달합니다. Z 문자의 2회 대기와 LF의 1회 대기를 삽입합니다. 마지막에는 ready에 X(미정), Z(고임피던스)를 각각 제시하여 전달과 비수락을 확인합니다. 문자 Z(0x5A)와 논리 Z는 다른 개념입니다.

수락 시점은 15, 55, 85ns이며 35, 45, 75ns는 대기입니다. 105, 125ns의 X/Z는 수락 수에 포함하지 않습니다. 이 예제의 프레임은 바이트 순서일 뿐 UART 8N1 직렬 프레임의 시작·정지·패리티를 검사하지 않습니다.

숫자로 따라가는 바이트 순서

A=0x41=65, Z=0x5A=90, LF(Line Feed, 줄바꿈)=0x0A=10입니다. 세 바이트의 실제 수락 샘플은15·55·85ns입니다. Z에는35·45ns 두 번, LF에는75ns 한 번의 대기를 넣어 stalled=3이 됩니다.

105ns의 readyX와125ns의 readyZ는 case의 default로 들어가 unknown_ready를 늘리지만 accepted는 늘리지 않습니다. 문자 Z의5A와 논리Z는 다른 표현입니다. 마지막 입력을130ns에 정리하고 expect_ports의 #1 뒤131ns에 종료하므로 모니터는5~125ns의13상승 에지를 관찰합니다.

04BFM과 독립 모니터의 역할

send_byte()는 입력을 구동하고 expect_ports()는 #1 뒤 조합 출력의 일치 여부를 비교합니다. 별도 always @(posedge tb_clk)는 BFM 호출 여부와 무관하게 모든 상승 에지를 검사합니다. 수락 횟수는 모니터에서만 증가시켜 중복 수락이나 순서 변경을 발견합니다.

검사방법
조합 전달세 포트의 !== 비교
대기 유지previous_stall과 held_data로 다음 샘플 확인
수락 순서accepted 값으로 41 → 5A → 0A 비교
X/Zcase의 default에서 unknown_ready 집계
종료accepted=3, stalled=3, unknown_ready=2, checks=14

!==는 X/Z를 포함한 비트 비교입니다. 이번 시험은 예상 X/Z의 그대로 전파를 요구하므로 미정값이 일치하는 것은 의도된 정상 결과입니다. 일반 정상 거래에서 X/Z를 허용한다는 뜻은 아닙니다. 모니터는 표본 사이의 순간 글리치나 실제 직렬 수신 오류를 검출하지 않습니다.

모니터 상태와 BFM 절차의 분리

expect_ports는 호출할 때만 세 조합 관계를 검사합니다. 모니터는 호출과 무관하게 매 상승 에지에서 연결·이전 대기 유지·실제 수락 순서를 봅니다. accepted는 모니터만 증가시키므로 BFM이 스스로 보냈다고 생각한 횟수를 결과처럼 재사용하지 않습니다.

모니터의 case(accepted)는 첫 수락이41, 둘째5A, 셋째0A여야 함을 정합니다. 네 번째가 생기면 EXTRA_ACCEPT로 끝납니다. 단순히 총3회만 세는 것보다 순서와 초과 거래를 더 확인합니다. 다만 샘플 사이 글리치와 모든 프로토콜 오류를 전수 검출하는 모델은 아닙니다.

05테스트벤치 전체 코드

tb/ch13/tb_uart_stream.sv · SystemVerilog
`timescale 1ns/1ps
// 제13장: 기존 조합형 UART Echo Controller의 Byte Stream BFM 검증.
// 주의: 이 DUT는 UART 직렬 비트 프레임을 해독하지 않는다.
// 이 장의 '프레임'은 TB가 구성하는 바이트 거래 시퀀스이다.
module tb_uart_stream;
    reg [7:0] rx_data_i = 8'h00;
    reg rx_valid_i = 1'b0;
    reg tx_ready_i = 1'b0;
    wire rx_ready_o, tx_valid_o;
    wire [7:0] tx_data_o;
    integer checks = 0;
    integer accepted = 0;
    // (추가) 모든 샘플 에지를 감시하는 독립 모니터 상태.
    integer stalled = 0, unknown_ready = 0;
    reg previous_stall = 1'b0;
    reg [7:0] held_data;

    uart_echo_controller dut (
        .rx_data_i(rx_data_i), .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o), .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o), .tx_ready_i(tx_ready_i)
    );

    // TB 가상 샘플 클록: DUT에 연결되지 않는다.
    reg tb_clk = 0;
    always #5 tb_clk = ~tb_clk;

    // (추가) 수락 카운트는 BFM이 아니라 매 상승 에지 모니터가 관리한다.
    always @(posedge tb_clk) begin
        if (tx_data_o !== rx_data_i || tx_valid_o !== rx_valid_i ||
            rx_ready_o !== tx_ready_i)
            $fatal(1, "FAIL MONITOR_PORTS");
        // 직전 샘플에서 대기했다면 다음 샘플까지 데이터와 valid를 유지.
        if (previous_stall &&
            (tx_valid_o !== 1'b1 || tx_data_o !== held_data))
            $fatal(1, "FAIL HOLD");
        previous_stall = 1'b0;
        if (tx_valid_o === 1'b1) begin
            case (tx_ready_i)
                1'b0: begin
                    stalled++;
                    previous_stall = 1'b1;
                    held_data = tx_data_o;
                end
                1'b1: begin
                    case (accepted)
                        0: if (tx_data_o !== 8'h41) $fatal(1, "FAIL ORDER A");
                        1: if (tx_data_o !== 8'h5A) $fatal(1, "FAIL ORDER Z");
                        2: if (tx_data_o !== 8'h0A) $fatal(1, "FAIL ORDER LF");
                        default: $fatal(1, "FAIL EXTRA_ACCEPT");
                    endcase
                    accepted++;
                    $display("ACCEPT t=%0d ns data=%h", $time, tx_data_o);
                end
                default: unknown_ready++; // X/Z는 확정 수락이 아니다.
            endcase
        end
    end

    // 조합회로 안정화 후 모든 공개 출력의 4상태 비교.
    task automatic expect_ports(
        input [7:0] data, input valid, input ready
    );
        begin
            #1;
            if (tx_data_o !== data || tx_valid_o !== valid ||
                rx_ready_o !== ready)
                $fatal(1, "FAIL data=%h valid=%b ready=%b", 
                       tx_data_o, tx_valid_o, rx_ready_o);
            checks = checks + 1;
        end
    endtask

    // BFM: 입력 바이트를 준비하고, 준비가 돌아올 때까지 유지한다.
    // stall_cycles는 수락 이전에 ready=0으로 유지할 샘플 수.
    task automatic send_byte(
        input [7:0] data, input integer stall_cycles
    );
        integer k;
        begin
            @(negedge tb_clk);
            rx_data_i = data;
            rx_valid_i = 1'b1;
            tx_ready_i = 1'b0;
            for (k = 0; k < stall_cycles; k = k + 1) begin
                expect_ports(data, 1'b1, 1'b0);
                @(posedge tb_clk);
                if (rx_ready_o !== 1'b0)
                    $fatal(1, "FAIL stall handshake");
                @(negedge tb_clk);
            end
            tx_ready_i = 1'b1;
            expect_ports(data, 1'b1, 1'b1);
            @(posedge tb_clk);
            // (변경) 수락과 순서는 독립 상승 에지 모니터가 판정한다.
            if (rx_valid_i !== 1'b1 || rx_ready_o !== 1'b1)
                $fatal(1, "FAIL acceptance");
            @(negedge tb_clk);
            rx_valid_i = 1'b0;
            expect_ports(data, 1'b0, 1'b1);
        end
    endtask

    initial begin
        #2000;
        $fatal(1, "FAIL GLOBAL_TIMEOUT");
    end

`ifdef VCD
    // (변경) Icarus에서 조건부 파형 기록.
    initial begin
        $dumpfile("ch13_uart_stream.vcd");
        $dumpvars(0, tb_uart_stream);
    end
`endif
    initial begin
        // 비활성 상태: valid=0이면 데이터가 있어도 거래가 아니다.
        expect_ports(8'h00, 1'b0, 1'b0);
        // 문자 A, Z, 줄바꿈: 3바이트 프레임의 교육용 표현.
        send_byte(8'h41, 0);
        send_byte(8'h5A, 2);
        send_byte(8'h0A, 1);
        // UART 물리 계층의 패리티/프레이밍 오류는 이 DUT에 포트가 없다.
        // 대신 준비 신호의 비정상 X 전파를 관찰하는 시험.
        @(negedge tb_clk);
        rx_valid_i = 1'b1;
        rx_data_i = 8'h45;
        tx_ready_i = 1'bx;
        expect_ports(8'h45, 1'b1, 1'bx);
        @(negedge tb_clk);
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b0;
        expect_ports(8'h45, 1'b0, 1'b0);
        // (추가) 고임피던스 Z도 전파되며 확정 수락되지 않는다.
        @(negedge tb_clk);
        rx_valid_i = 1'b1;
        rx_data_i = 8'h46;
        tx_ready_i = 1'bz;
        expect_ports(8'h46, 1'b1, 1'bz);
        @(negedge tb_clk);
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b0;
        expect_ports(8'h46, 1'b0, 1'b0);
        if (stalled != 3 || unknown_ready != 2 || previous_stall)
            $fatal(1, "FAIL monitor counts");
        if (accepted != 3 || checks != 14)
            $fatal(1, "FAIL count accepted=%0d checks=%0d", accepted, checks);
        $display("MONITOR stalled=%0d unknown_ready=%0d", stalled, unknown_ready);
        $display("PASS CH13 accepted=%0d checks=%0d", accepted, checks);
        $finish;
    end
endmodule

전체 코드 · 두 검사 계수의 의미

포트 검사 checks14는 초기1, 세 바이트의 수락 전·유휴 확인6, 대기3, X/Z 전후4를 합한 값입니다. 모니터의13상승 에지와 수락3은 각각 다른 단위입니다. 한 숫자를 전체 검사 횟수처럼 합쳐 해석하지 않습니다.

의도적으로 ready에 X/Z를 넣는 두 사례에서는 그 상태가 rx_ready_o까지 전달되는 것이 정답입니다. 이 때문에 !==로 동일한 X/Z를 일치시킵니다. 제09장의 정상 출력 X 금지와 모순이 아니라 시험의 요구가 다릅니다. 데이터·제어가 항상 확정되어야 하는 정상 거래와 구별합니다.
