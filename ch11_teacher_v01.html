00개요 · 파형을 시간 규칙으로 표현한다

SVA(SystemVerilog Assertions, 시스템베릴로그 어설션)는 신호 사이의 시간 관계를 선언하고 위반을 자동 검사하는 문법입니다. 제09장에서는 매 클록 기대값을 비교했고 제10장에서는 오류 검출 경로를 확인했습니다. 이제 어떤 조건이 성립하면 언제까지 어떤 결과가 나타나야 하는가를 속성으로 표현합니다.

선행 설계 학습안내서: 제2부 사용자 AXI IP와 주변장치(amd_soc_p2), 04.2장 「RTL · AXI 풀이」 02절 「설정 Shadow와 출력 Active를 분리」 및 06절 「독립 PWM Core 전체」, pwm_core.v. AXI 래퍼는 검증 대상이 아닙니다.

01원본 RTL과 시간 계약

원본은 상승 에지에서 요청을 Shadow에 저장하고 주기 경계에서 기존 대기 설정을 Active로 반영합니다. 동기 리셋과 조합 출력 차단을 구별합니다. 실습은 주기 8클록, 클록 10ns, 정상 극성으로 제한합니다.

reference_rtl/pwm_core.v · Verilog
`timescale 1ns/1ps
// P2-04: 보드와 무관한 단일 채널 범용 PWM 코어.
// (추가) period와 duty는 클록 횟수 단위. 0%/100%는 지속 LOW/HIGH.
// (추가) 설정은 주기 마지막 경계에서만 활성값으로 반영.
module pwm_core #(
    parameter [31:0] RESET_PERIOD = 32'd100000
)(
    input  wire        clk,
    input  wire        resetn,
    input  wire        cfg_apply,
    input  wire [31:0] cfg_period,
    input  wire [31:0] cfg_duty,
    input  wire        cfg_enable,
    input  wire        cfg_polarity,
    output wire        pwm_out,
    output reg         pending,
    output reg [31:0] active_period,
    output reg [31:0] active_duty,
    output reg         active_enable,
    output reg         active_polarity
);
    reg [31:0] counter;
    reg [31:0] shadow_period;
    reg [31:0] shadow_duty;
    reg        shadow_enable;
    reg        shadow_polarity;

    wire boundary = (counter >= active_period - 32'd1);
    wire duty_high = (counter < active_duty);

    // (주의) enable=0이면 polarity와 관계없이 LOW로 차단.
    // (설명) 기본 polarity에서 active_duty=0이면 항상 LOW,
    //         active_duty=active_period이면 항상 HIGH.
    assign pwm_out = resetn && active_enable &&
                     (active_polarity ? !duty_high : duty_high);

    always @(posedge clk) begin
        if (!resetn) begin
            counter         <= 32'd0;
            active_period   <= RESET_PERIOD;
            active_duty     <= 32'd0;
            active_enable   <= 1'b0;
            active_polarity <= 1'b0;
            shadow_period   <= RESET_PERIOD;
            shadow_duty     <= 32'd0;
            shadow_enable   <= 1'b0;
            shadow_polarity <= 1'b0;
            pending         <= 1'b0;
        end else begin
            if (boundary) begin
                counter <= 32'd0;
                if (pending) begin
                    active_period   <= shadow_period;
                    active_duty     <= shadow_duty;
                    active_enable   <= shadow_enable;
                    active_polarity <= shadow_polarity;
                    pending         <= 1'b0;
                end
            end else begin
                counter <= counter + 32'd1;
            end
            // (추가) 경계와 APPLY가 겹치면 새 값은 다음 경계에 적용.
            // 여러 APPLY가 겹치면 최종 요청값을 우선하는 단일 Shadow 구조.
            if (cfg_apply) begin
                shadow_period   <= cfg_period;
                shadow_duty     <= cfg_duty;
                shadow_enable   <= cfg_enable;
                shadow_polarity <= cfg_polarity;
                pending         <= 1'b1;
            end
        end
    end
endmodule

DUT(디유티, 검증 대상 회로)의 7개 입력과 6개 출력을 그대로 사용합니다. 어설션은 내부 counter를 읽지 않으며 원본을 변경하지 않습니다.

DUT 시간 계약과 속성의 역할

기존 PWM의 요청 저장은 상승 에지 NBA에서 일어납니다. 반면 동시 어설션은 에지 직전 값을 샘플링합니다. 따라서 코드의 순서가 아니라 사건 처리 영역과 관찰 기준을 먼저 확인해야 합니다. 원본 RTL에는 속성 코드를 삽입하지 않고 공개 포트에 대해 TB에서 검사합니다.

02같은 샘플과 다음 샘플 · |-> / |=>

동시 어설션은 상승 에지의 Preponed(프리폰드, 선행 샘플링 영역)에서 값을 샘플링합니다. DUT의 비차단 대입은 NBA(Nonblocking Assignment, 비차단 대입 갱신 영역)에서 반영되므로 해당 에지에서 샘플한 값과 갱신된 값은 다릅니다.

표현단일 클록 선행 조건에서의 뜻
A |-> BA가 참이면 같은 샘플에서 B 검사
A |=> BA가 참이면 다음 상승 에지 샘플에서 B 검사
disable iff (!resetn)리셋 중 속성 시도를 비활성화하거나 진행 중 시도를 취소

리셋 출력 자체를 검사하는 ap_reset_low에는 disable iff를 사용하지 않습니다. disable iff는 일반 속성의 샘플값과 달리 비샘플 조건으로 리셋에 반응할 수 있습니다. 이 실습의 리셋은 상승 에지와 겹치지 않게 구동합니다.

판서 · 45ns의 두 가지 상태

시점·영역apply / pending의미
40ns 하강 에지 뒤1 / 0TB가 첫 요청을 구동합니다.
45ns 에지 직전 샘플1 / 0속성은 apply=1을 선행 조건으로 봅니다.
45ns NBA 뒤1 / 1DUT가 Shadow와 pending을 갱신합니다.
55ns 에지 직전 샘플0 / 1|=>의 다음 샘플 결론을 검사합니다.

단일 샘플 선행 조건에서는 |->가 같은 샘플, |=>가 다음 샘플입니다. 일반적인 여러 클록 길이 시퀀스로 확장할 때는 선행 시퀀스의 끝을 기준으로 결론 시작을 해석해야 합니다. 현재 한 에지 조건에 대한 설명을 모든 복합 속성의 임의 시점 규칙으로 확대하지 않습니다.

disable iff는 일반 속성의 샘플값과 다른 비샘플 취소 조건입니다. 리셋 중 일반 동작을 검사하지 않도록 진행 시도를 취소할 수 있습니다. 리셋 출력 자체를 검사하는 ap_reset_low까지 비활성화하면 리셋 성질을 보지 못하므로 그 속성에는 사용하지 않습니다.

03다섯 속성의 의미와 적용 범위

속성 이름선행 조건검사할 결론
ap_reset_low!resetn같은 샘플 !pwm_out
ap_disabled_low!active_enable같은 샘플 !pwm_out
ap_apply_pendingcfg_apply다음 샘플 pending
ap_zero_dutyenable·정상 극성·duty 0같은 샘플 LOW
ap_full_dutyenable·정상 극성·period 8·duty 8같은 샘플 HIGH

cfg_apply가 주기 경계와 겹쳐도 마지막 NBA 대입이 pending을 1로 설정하므로 다음 샘플에서 확인할 수 있습니다. 단, 해당 시도가 리셋으로 취소되지 않는 경우입니다. 이 속성만으로 설정이 정확한 경계에 반영되었다는 사실까지 증명하지는 못합니다.

Vacuous pass(배큐어스 패스, 선행 조건이 거짓이라 위반 없이 통과하는 경우)는 정상적인 논리 의미이지만 검증 입력이 부족하다는 사실을 가릴 수 있습니다. 예를 들어 100% 듀티를 한 번도 적용하지 않아도 ap_full_duty가 위반되지 않습니다. 따라서 각 선행 조건이 실제로 발생하는지 별도 카운터로 집계합니다. 이는 SVA 엔진의 성공 횟수나 정식 기능 커버리지와 다릅니다.

공허한 통과와 구별력 있는 자극

조건이 한 번도 참이 아니면 함의가 위반되지 않을 수 있습니다. 100%를 적용하지 않고 full 속성이 실패하지 않았다고 보고해도 그 동작을 시험한 증거는 없습니다. 그래서 *_hits로 선행 조건이 실제 발생했는지 셉니다. 이것은 SVA 엔진의 성공 횟수나 covergroup 측정값이 아닙니다.

조건 발생만으로도 부족할 수 있습니다. enable0을 duty0에서만 시험하면 enable 차단이 누락된 DUT도 비교식 자체가 LOW여서 통과합니다. 최신 v05는 enable0·duty4를 적용해 차단이 없으면 HIGH가 될 구간에서 LOW를 검사합니다. disabled_duty_hits는 이 더 구별력 있는 표본이 있었는지 확인합니다.

정상 입력에서 X·Z를 금지하는 별도 검사도 필요합니다. 미정 선행 조건이 참이 되지 않으면 속성의 오류 경로가 활성화되지 않을 수 있기 때문입니다.

두 번째 요청은 185ns 경계와 동시에 수락되며 새 값은 265ns에 적용됩니다. 455ns의 갱신 후 듀티 4에서 counter는 3이므로 출력은 HIGH입니다. 460ns에 리셋을 인가하고 461ns에 LOW인지 확인합니다. 다음 상승 에지 465ns에서 내부 상태가 초기화됩니다. 480ns에 리셋을 해제하고 마지막 듀티 2를 시험합니다.

이 시간표는 고정 8클록 경계와 TB의 하강 에지 대기를 계산한 예상값입니다. 12클록 대기 후의 검사로 최종 적용을 확인하지만 정확한 반영 시점 전체를 검증하는 속성은 아닙니다.

최신 v05의 다섯째 요청까지 연결하기

위 시간표는 apply_duty의 네 호출입니다. 이들은 요청 40·180·320·490ns, 절차 확인 170·310·450·620ns입니다. 첫 리셋 해제가 30ns이므로 주기 경계는 105·185·265·345·425ns로 진행합니다. 이전 장과 다른 초기 리셋 길이 때문에 첫 경계 시각도 달라집니다.

v05 추가 시나리오는 네 번째 확인 뒤 630ns에 enable0·duty4를 요청하고 635ns 경계에서 저장합니다. 해당 경계의 이전 pending은 0이므로 715ns에 반영됩니다. 725·735·745·755ns의 에지 직전 표본 네 개가 disabled_duty_hits에 들어가고 760ns에 종료합니다. 따라서 절차 checks=4와 실제 apply_hits=5가 동시에 옳습니다.

리셋은 HIGH 선행 조건을 확인한 460ns에 인가하고 461ns에 출력0을 관찰합니다. 상태 리셋은 465ns 에지입니다. SVA의 에지 샘플만으로 두 에지 사이 즉시 차단을 모두 확인할 수 없어 절차 검사를 함께 둡니다.

`timescale 1ns/1ps
// 제11장: 기존 pwm_core 공개 포트에 SVA 시간 계약을 적용한다.
// SVA를 지원하는 SystemVerilog 시뮬레이터에서만 실행한다.
module tb_pwm_sva;
  logic clk = 0, resetn = 0, cfg_apply = 0;
  logic [31:0] cfg_period = 8, cfg_duty = 0;
  logic cfg_enable = 1, cfg_polarity = 0;
  wire pwm_out, pending, active_enable, active_polarity;
  wire [31:0] active_period, active_duty;
  integer checks = 0;
  // (추가) 어설션 관찰 경로의 의도된 실패 시험. DUT는 수정하지 않는다.
  bit inject_sva_pending = 0;
  // (추가) 속성의 선행 조건 발생 횟수. SVA 엔진의 통과 횟수와 구별한다.
  integer reset_hits = 0, disabled_hits = 0, apply_hits = 0;
  integer zero_hits = 0, full_hits = 0;
  // (추가) enable=0이면서 duty>0인 표본. enable 차단이 빠지면 출력이
  // HIGH가 되는 구간이므로 ap_disabled_low가 결함을 구별할 수 있다.
  integer disabled_duty_hits = 0;

  pwm_core #(.RESET_PERIOD(32'd8)) dut (
    .clk(clk), .resetn(resetn), .cfg_apply(cfg_apply),
    .cfg_period(cfg_period), .cfg_duty(cfg_duty),
    .cfg_enable(cfg_enable), .cfg_polarity(cfg_polarity),
    .pwm_out(pwm_out), .pending(pending),
    .active_period(active_period), .active_duty(active_duty),
    .active_enable(active_enable), .active_polarity(active_polarity)
  );
  always #5 clk = ~clk;

  // 리셋 중 출력은 LOW. 조합 차단은 별도 즉시 검사로 보강한다.
  ap_reset_low: assert property (
    @(posedge clk) !resetn |-> !pwm_out
  ) else $fatal(1, "FAIL SVA reset output");

  // Enable=0이면 극성과 무관하게 출력은 LOW.
  ap_disabled_low: assert property (
    @(posedge clk) disable iff (!resetn)
      !active_enable |-> !pwm_out
  ) else $fatal(1, "FAIL SVA disabled output");

  // cfg_apply는 상승 에지에 캡처되고 pending은 다음 샘플에 1.
  // 경계와 겹쳐도 cfg_apply 대입이 마지막이므로 pending=1.
  ap_apply_pending: assert property (
    @(posedge clk) disable iff (!resetn)
      cfg_apply |=> (pending && !inject_sva_pending)
  ) else begin
    // (추가) 실제 샘플 pending이 1인데 관찰 경로만 차단했을 때의 진단.
    if (inject_sva_pending && ($sampled(pending) === 1'b1))
      $fatal(1, "DETECTED_SVA_PENDING t=%0d", $time);
    else
      $fatal(1, "FAIL SVA apply pending");
  end

  // 주기·듀티가 8/0이고 정상 극성이면 출력은 LOW.
  ap_zero_duty: assert property (
    @(posedge clk) disable iff (!resetn)
      (active_enable && !active_polarity &&
       active_duty == 32'd0) |-> !pwm_out
  ) else $fatal(1, "FAIL SVA zero duty");

  // 8/8의 100% 듀티는 정상 극성에서 HIGH.
  ap_full_duty: assert property (
    @(posedge clk) disable iff (!resetn)
      (active_enable && !active_polarity &&
       active_period == 32'd8 &&
       active_duty == 32'd8) |-> pwm_out
  ) else $fatal(1, "FAIL SVA full duty");

  // (추가) 상승 에지 직전 상태를 읽는 선행 조건 집계.
  // TB 자극은 하강 에지, DUT 상태 갱신은 NBA에서 수행한다.
  always @(posedge clk) begin
    if (!resetn)
      reset_hits++;
    else begin
      if ((^{pwm_out, pending, active_period, active_duty,
             active_enable, active_polarity}) === 1'bx)
        $fatal(1, "FAIL UNKNOWN_OUTPUT");
      if (!active_enable) disabled_hits++;
      if (!active_enable && !active_polarity && active_duty != 32'd0)
        disabled_duty_hits++;
      if (cfg_apply) apply_hits++;
      if (active_enable && !active_polarity &&
          active_duty == 32'd0) zero_hits++;
      if (active_enable && !active_polarity &&
          active_period == 32'd8 && active_duty == 32'd8)
        full_hits++;
    end
  end

  task automatic apply_duty(input logic [31:0] duty);
    @(negedge clk);
    cfg_duty = duty;
    cfg_apply = 1;
    @(negedge clk);
    cfg_apply = 0;
    repeat (12) @(negedge clk);
    if (active_duty !== duty || pending !== 1'b0)
      $fatal(1, "FAIL APPLY duty=%0d actual=%0d pending=%b",
             duty, active_duty, pending);
    checks++;
  endtask

  initial begin
    #2000;
    $fatal(1, "FAIL GLOBAL_TIMEOUT");
  end
  initial begin
    inject_sva_pending = $test$plusargs("INJECT_SVA_PENDING");
`ifdef VCD
    $dumpfile("ch11_pwm_sva.vcd");
    $dumpvars(0, tb_pwm_sva);
`endif
    repeat (3) @(negedge clk);
    resetn = 1;
    apply_duty(32'd0);
    apply_duty(32'd8);
    apply_duty(32'd4);
    // 클록 사이에서 LOW 리셋을 걸면 PWM 출력은 즉시 차단된다.
    @(negedge clk);
    // (추가) 정상 HIGH 상태에서 리셋을 인가해야 출력 차단을 시험할 수 있다.
    if (pwm_out !== 1'b1)
      $fatal(1, "FAIL RESET_PRECONDITION");
    resetn = 0;
    #1;
    if (pwm_out !== 1'b0)
      $fatal(1, "FAIL RESET_GATE");
    repeat (2) @(negedge clk);
    resetn = 1;
    apply_duty(32'd2);
    // (추가) enable=0, duty=4를 적용한다. 정상 DUT의 출력은 LOW를 유지한다.
    @(negedge clk);
    cfg_enable = 0;
    cfg_duty = 32'd4;
    cfg_apply = 1;
    @(negedge clk);
    cfg_apply = 0;
    repeat (12) @(negedge clk);
    if (active_enable !== 1'b0 || active_duty !== 32'd4 || pending !== 1'b0)
      $fatal(1, "FAIL DISABLE_APPLY");
    // (추가) 선행 조건 미발생으로 인한 공허한 통과를 방지한다.
    if (checks != 4 || apply_hits != 5 || reset_hits == 0 ||
        disabled_hits == 0 || disabled_duty_hits == 0 ||
        zero_hits == 0 || full_hits == 0)
      $fatal(1, "FAIL SVA ACTIVATION");
    $display("ACTIVATION reset=%0d disabled=%0d disabled_duty=%0d apply=%0d zero=%0d full=%0d",
             reset_hits, disabled_hits, disabled_duty_hits, apply_hits,
             zero_hits, full_hits);
    $display("PASS CH11 SVA checks=%0d", checks);
    $finish;
  end
endmodule

전체 TB 읽기 · 세 종류의 검사 결과

다섯 assert property는 시간 성질을 검사하고, apply_duty의 checks는 네 번의 최종 적용을 검사하며, *_hits는 입력·상태 조건이 출현했는지 셉니다. 이 세 집계를 하나의 ‘어설션 통과 수’로 합치지 않습니다. apply_duty가 12클록 뒤에 목표값을 확인한다고 정확한 모든 중간 적용 시점을 검증한 것도 아닙니다.

부정 모드는 실제 DUT pending을 바꾸지 않고 속성의 결론에 !inject_sva_pending을 더해 거짓으로 만듭니다. 실패 action block에서는 $sampled(pending)을 읽어 해당 속성이 본 pending이 정상1이었는지 확인한 뒤 전용 진단을 냅니다. 현재값과 샘플값을 섞지 않으려는 선택입니다.

06실행 · Vivado XSIM

어설션 활성화 검증: 정상 실행 외에 +INJECT_SVA_PENDING을 전달하는 부정 시험을 수행합니다. ap_apply_pending의 결론을 의도적으로 거짓으로 만들어, 정상 DUT의 pending이 1인 상태에서 55ns에 DETECTED_SVA_PENDING이 발생하는지 확인합니다. 실제 DUT 출력은 수정하지 않습니다. 이 검사는 해당 속성의 실패 경로를 입증하는 시험이며, 다섯 속성 전체의 검증을 보장하지 않습니다.

AMD UG900 2024.1 및 2026.1의 지원표에서 concurrent assertion, implication, assert statement, disable iff 지원이 명시되어 있습니다. 설치된 버전에서 직접 확인합니다. Icarus의 전체 동시 어설션 지원을 전제하지 않습니다.

Ubuntu · Vivado XSIM 실행 스크립트
#!/usr/bin/env bash
# 제11장: 독립 저장소의 원본 RTL과 SVA 테스트벤치를 XSIM으로 실행.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
RTL="${1:-$ROOT/reference_rtl/pwm_core.v}"
TB="$ROOT/tb/ch11/tb_pwm_sva.sv"
OUT="$ROOT/.build/ch11/xsim"
if [[ ! -f "$RTL" || ! -f "$TB" ]]; then
  echo "FAIL: RTL 또는 TB 파일 없음" >&2
  exit 1
fi
# (변경) 상대 경로도 작업 폴더 이동 전에 절대 경로로 변환.
RTL="$(realpath "$RTL")"
for tool in xvlog xelab xsim; do
  if ! command -v "$tool" >/dev/null 2>&1; then
    echo "NOT_RUN: $tool 미설치 또는 Vivado 환경 미설정" >&2
    exit 2
  fi
done
mkdir -p "$OUT"
cd "$OUT"
xvlog "$RTL"
xvlog -sv "$TB"
xelab -debug typical tb_pwm_sva -s ch11_sim
xsim ch11_sim -runall -onerror quit 2>&1 | tee ch11.log
grep -q '^PASS CH11 SVA checks=4$' ch11.log
if grep -q 'FAIL SVA\|FAIL APPLY\|FAIL RESET\|FAIL UNKNOWN\|FAIL GLOBAL\|DETECTED_SVA_PENDING' ch11.log; then
  echo "FAIL: 검증 오류 로그 발견" >&2
  exit 1
fi

# (추가) 어설션 엔진의 의도된 실패 경로를 별도 실행으로 확인한다.
# XSIM 종료 코드의 버전 차이를 고려해 진단과 정상 완료 부재를 검사한다.
rc=0
xsim ch11_sim -runall -onerror quit -testplusarg INJECT_SVA_PENDING \
  > ch11_negative.log 2>&1 || rc=$?
grep -q 'DETECTED_SVA_PENDING t=55' ch11_negative.log
if grep -q 'PASS CH11 SVA\|FAIL SVA\|FAIL APPLY\|FAIL RESET\|FAIL UNKNOWN\|FAIL GLOBAL' ch11_negative.log; then
  echo "FAIL: 부정 시험에서 기대하지 않은 결과 발생" >&2
  exit 1
fi
echo "PASS CH11 HARNESS: SVA 오류 검출 (xsim exit=$rc)"

07예상 결과와 반례

부정 시험의 예상 진단은 DETECTED_SVA_PENDING t=55이며 정상 완료 문구가 없어야 합니다. 부정 시험도 정상 PASS로 끝난다면 어설션 무시 옵션 또는 속성 활성화를 확인합니다.

예상 로그 · XSIM 2024.2·Verilator 5.054 실측과 일치
ACTIVATION reset=5 disabled=20 disabled_duty=4 apply=5 zero=16 full=8
PASS CH11 SVA checks=4

위 카운터는 정상 입력의 에지 직전 조건을 계산한 예상값입니다. 네 번의 적용 검사와 다섯 속성의 활성 여부를 구별합니다.

반례는 논리적으로 분석한 예상 검출입니다. 실제 오류 주입 시험을 별도로 수행해야 검증 환경이 어설션을 실행하는지 확인할 수 있습니다. 샘플 사이 글리치나 일반 주기 변경, 전체 PWM 위상에 대한 정식 증명은 이 장의 범위 밖입니다. 다음 장에서는 Functional Coverage(펑셔널 커버리지, 기능별 시험 범위 측정)로 입력 조합의 누락 여부를 확인합니다.

v04의 TB는 Vivado XSIM 2024.2에서 종료 코드 0 · PASS였습니다. v05에서는 enable=0·duty=4 시험을 추가했습니다. 개정 TB는 2026-11-26 Vivado XSIM 2024.2에서 종료 코드 0 · PASS였고, 부정 시험도 검출했습니다(PASS CH11 HARNESS). Verilator 5.054에서도 같은 결과를 확인했습니다.

수치 해석과 예상 문답

reset_hits=5는 초기 5·15·25ns와 중간 465·475ns입니다. zero=16과 full=8은 정상 출력 조건이 참이었던 에지 수이고, apply=5는 요청이 상승 에지에서 보인 수입니다. disabled=20에는 초기·중간 리셋 해제 뒤 활성 전 구간과 마지막 비활성 구간이 들어가며, 그중 duty가 양수인 마지막 네 표본이 disabled_duty=4입니다.

카운터가 예상값이면 속성도 성공인가요? 카운터는 선행 조건의 출현 증거입니다. 속성 위반은 엔진의 action block이 따로 판정하며 둘을 함께 확인해야 합니다.

assert가 있으면 합성 회로가 추가되나요? 현재 속성은 TB의 시뮬레이션 검사입니다. 검증용 선언을 곧바로 FPGA 구현 회로로 해석하지 않습니다. 다음 장의 기능 커버리지는 별도의 질문인 ‘계획한 조합을 얼마나 시험했는가’를 다룹니다.
