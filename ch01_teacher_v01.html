제01장 · 테스트벤치의 첫 실행

원본 UART Echo RTL을 변경하지 않고 입력 자극과 출력 관찰을 수행하는 첫 실습

교수용 보충자료 · v01입출력 관찰기존 RTL 재사용

원본 학습안내서 제01장 · 원본 v05의 절·그림·전체 소스를 유지한 교수용 보충 해설

00개요 · 무엇을 검증하는가

회로가 정상인지 확인하려면 먼저 입력에 대해 어떤 출력이 나와야 하는지 알아야 합니다. Testbench(테스트벤치, 시험 환경)는 실제 회로 대신 입력을 만들어 주고, 그 결과를 관찰하는 시뮬레이션 코드입니다.

검증 대상은 UART Echo Controller(유아트 에코 제어기)입니다. UART에서 수신한 바이트를 송신 경로로 전달하는 준비 단계 회로이며, UART 직렬 프레임을 직접 생성하거나 해석하는 회로는 아닙니다. 세 가지 조합 연결을 확인하는 것부터 시작합니다.

선행 설계 학습안내서: Basys3 소형 NPU 실습(amd_soc_npu) 제1장 UART 계산기, 03절 「서브젝트 1-1 · UART 에코」의 uart_echo_controller.v. 이 장은 에코 제어기만 시험하며 UART 송수신기 전체를 검증하지 않습니다.

교수용 설명 · 검증이 필요한 이유

수업에서 이렇게 설명합니다. 회로 설계는 '무엇을 만들 것인가', 검증은 '만든 회로가 약속한 일을 하는가'를 묻는 과정입니다. 스위치와 LED를 연결했다면 스위치를 바꿔 보아야 회로의 기능을 알 수 있습니다. 여기서는 스위치 대신 TB(Testbench, 테스트벤치, 시험 환경)가 값을 공급하고, LED 대신 출력 신호와 콘솔을 읽습니다.

구분실제 대상수업에서 강조할 역할
설계uart_echo_controller입력과 출력을 연결하는 회로
시험 환경tb_uart_echo_basics입력값을 바꾸고 결과를 관찰
검증 기준세 연속 대입의 입출력 관계기대 출력과 관찰값의 비교 기준

UART(Universal Asynchronous Receiver/Transmitter, 유아트, 범용 비동기 송수신)는 이후 통신 전체를 다룰 때 필요합니다. 지금은 8비트 바이트와 준비·유효 신호만 다룹니다. FPGA 보드나 UART 케이블 없이도 논리 시뮬레이션이 가능합니다.

01원본 RTL · UART Echo Controller

RTL(Register Transfer Level, 레지스터 전송 수준)로 작성된 원본의 전체 내용입니다. DUT(Device Under Test, 검증 대상 회로)에는 클록, 리셋, 내부 레지스터가 없습니다. 이 회로의 기능은 세 개의 연속 대입문으로 완결됩니다.

reference_rtl/uart_echo_controller.v · Verilog · 원본 동일
// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.
module uart_echo_controller(
    input wire [7:0] rx_data_i,
    input wire rx_valid_i,
    output wire rx_ready_o,
    output wire [7:0] tx_data_o,
    output wire tx_valid_o,
    input wire tx_ready_i
);
    assign rx_ready_o=tx_ready_i;
    assign tx_valid_o=rx_valid_i;
    assign tx_data_o=rx_data_i;
endmodule

위 코드 전체를 reference_rtl/uart_echo_controller.v로 저장합니다. 원본 저장소에 접속할 필요가 없습니다.

가운데 상자만 실제 RTL 모듈입니다. 좌우는 테스트벤치가 구동하거나 관찰하는 신호이며, 별도의 UART 송수신 모듈이 존재한다는 뜻이 아닙니다. 각 화살표는 DUT 경계에서 신호의 입력·출력 방향을 표시하고, 상자 내부에는 대응하는 원본 대입문을 제시합니다.

assign은 입력이 변하면 연결된 출력을 갱신하는 연속 대입입니다. 데이터와 유효 신호는 수신에서 송신 방향으로 전달되지만, 준비 신호는 반대 방향으로 전달됩니다. 송신 쪽이 준비되지 않았다면 앞단 역시 새로운 전달을 완료할 수 없음을 알게 됩니다.

원본 포트방향·폭동작
rx_data_i입력 · 8비트수신 바이트
rx_valid_i입력 · 1비트수신 데이터의 유효 여부
tx_ready_i입력 · 1비트송신 측 수락 가능 여부
tx_data_o출력 · 8비트rx_data_i 그대로 전달
tx_valid_o출력 · 1비트rx_valid_i 그대로 전달
rx_ready_o출력 · 1비트tx_ready_i 그대로 전달

Ready/Valid(레디/밸리드, 준비·유효 계약): 두 신호가 모두 1인 경우에만 전송 수락 조건이 성립합니다. 실제 동기식 시스템에서는 정해진 샘플링 클록에서 이 조건을 판단합니다. 이 DUT에는 클록이나 저장 기능이 없으므로 수락 횟수나 저장된 바이트를 스스로 관리하지 않습니다.

교수용 코드 풀이 · 원본 RTL 1~13행

원본 행실제 코드쉬운 풀이
1// (추가) 준비 단계 UART Echo controller: pure combinational stream transfer.주석입니다. 이 모듈은 저장 없이 스트림 신호를 그대로 연결하는 준비 단계 회로임을 알려 줍니다.

4 input wire rx_valid_i,앞단이 현재 바이트를 유효하다고 알리는 1비트 입력입니다.
5 output wire rx_ready_o,앞단에게 뒤쪽이 받을 준비가 되었는지 알려 주는 출력입니다.
6 output wire [7:0] tx_data_o,뒤쪽에 내보내는 8비트 데이터입니다.
7 output wire tx_valid_o,뒤쪽에게 출력 바이트가 유효한지 알려 줍니다.
8 input wire tx_ready_i뒤쪽에서 받은 준비 신호입니다. 데이터와 방향이 반대입니다.
9);포트 선언을 닫습니다.
10 assign rx_ready_o=tx_ready_i;송신 측의 준비 상태를 수신 측으로 그대로 전달합니다. 수락 가능 여부에 대한 역방향 배선입니다.
11 assign tx_valid_o=rx_valid_i;앞단의 유효 신호를 뒤쪽으로 그대로 연결합니다. ready가 0이어도 valid를 억지로 0으로 만들지 않습니다.
12 assign tx_data_o=rx_data_i;데이터 8비트를 그대로 연결합니다. valid가 0이어도 데이터선 값 자체는 전달되지만 의미 있는 바이트로 취급하지 않습니다.

Ready와 Valid를 구분하는 쉬운 비유

물건이 컨베이어 위에 있다는 표시가 valid이고, 받는 사람이 받을 수 있다는 표시가 ready입니다. 받는 사람이 준비되지 않아도 물건은 보일 수 있습니다. 이 회로는 두 표시를 전달하는 통로일 뿐이며 물건을 저장하는 창고가 아닙니다.

validready수락 조건설명
00불성립물건 없음, 수령 준비 없음
11성립유효한 물건과 준비가 동시에 존재
10불성립물건은 있지만 수령 불가
01불성립수령 준비만 완료

동기식 실제 인터페이스에서는 정해진 클록 에지에서 수락을 확정합니다. 이 조합 DUT에는 클록이 없으므로 수락 조건만 전달하고 실제 수락 횟수는 계산하지 않습니다.

02검증 구조와 입력 시나리오

파일 두 개를 함께 컴파일합니다. uart_echo_controller.v는 회로의 기능을 정의하고, tb_uart_echo_basics.sv는 그 회로를 dut라는 이름으로 연결합니다. TB의 입력 변수는 DUT 포트로 들어가며, DUT 출력은 TB의 연결 신호를 통해 읽습니다.

입력 유지 구간rx_data_irx_valid_itx_ready_i확인 내용
0~10ns0000유효하지 않고 준비도 안 됨
10~20ns41 (A)11전송 수락 조건 성립
20~30ns5A (Z)10유효하지만 수락 불가
30~40ns0001준비되었지만 유효 데이터 없음

각 구간 끝에서 값을 출력합니다. 이 예제는 독립적인 조합 입력 조건을 관찰하는 기초 시험이며, 30ns 이후 대기 중인 Z를 취소합니다. 실제 Ready/Valid 송신기는 수락 전까지 유효 데이터와 valid를 유지해야 하므로 이 자극을 완전한 통신 규약 시험으로 해석해서는 안 됩니다.

교수용 판서 · 자극과 관찰의 차이

입력 조건을 바꿀 때마다 출력 3개를 먼저 종이에 예측하도록 합니다. 핵심은 데이터의 16진수 값과 데이터의 유효성을 서로 다른 정보로 보는 것입니다.

유지 구간입력 data / valid / ready예측 출력 data / valid / ready관찰 시각
0–10ns00 / 0 / 000 / 0 / 010ns
10–20ns41 / 1 / 141 / 1 / 120ns
20–30ns5A / 1 / 05A / 1 / 030ns
30–40ns00 / 0 / 100 / 0 / 140ns

이 네 사례는 valid/ready의 가능한 네 조합을 한 번씩 보여 줍니다. 그러나 모든 데이터 값이나 시간적 프로토콜을 검증하는 것은 아닙니다. 특히 Z가 수락되지 않은 상태에서 valid를 내리는 것은 교육용 입력 전환이지 정상 송신기의 규약 검증이 아닙니다.

03테스트벤치 전체 소스

tb/ch01/tb_uart_echo_basics.sv · SystemVerilog · 기존 Icarus 관찰 실행 완료
`timescale 1ns/1ps
// 제01장: 기존 UART Echo Controller의 입출력을 관찰하는 첫 테스트벤치.
// 이 단계는 출력 표시가 목적이며, 자동 PASS/FAIL은 제04장에서 학습한다.
module tb_uart_echo_basics;
    // TB가 직접 구동하는 DUT 입력은 reg로 선언한다.
    reg  [7:0] rx_data_i;
    reg        rx_valid_i;
    reg        tx_ready_i;

    // DUT가 구동하는 출력은 wire로 관찰한다.
    wire       rx_ready_o;
    wire [7:0] tx_data_o;
    wire       tx_valid_o;

    // 기존 RTL의 실제 포트 이름과 1:1로 연결한다.
    uart_echo_controller dut (
        .rx_data_i (rx_data_i),
        .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o),
        .tx_data_o (tx_data_o),
        .tx_valid_o(tx_valid_o),
        .tx_ready_i(tx_ready_i)
    );

`ifdef VCD
    // Icarus Verilog 사용 시 -DVCD 옵션으로 파형 저장 기능을 켠다.
    initial begin
        $dumpfile("ch01_uart_echo.vcd");
        $dumpvars(0, tb_uart_echo_basics);
    end
`endif

    initial begin
        $display("=== CH01 UART ECHO TESTBENCH START ===");

        // 10ns: 유효 데이터가 없고 송신 준비도 안 된 상태.
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b0;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 20ns: 문자 'A'(ASCII 0x41)를 정상 전달한다.
        rx_data_i  = 8'h41;
        rx_valid_i = 1'b1;
        tx_ready_i = 1'b1;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 30ns: 뒤쪽 준비 신호를 내려 전송 대기를 관찰한다.
        rx_data_i  = 8'h5A;
        rx_valid_i = 1'b1;
        tx_ready_i = 1'b0;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        // 40ns: 유효 데이터 없이 준비 신호만 켠다.
        rx_data_i  = 8'h00;
        rx_valid_i = 1'b0;
        tx_ready_i = 1'b1;
        #10;
        $display("t=%0d ns rx=%02h rv=%b tr=%b | tx=%02h tv=%b rr=%b",
            $time, rx_data_i, rx_valid_i, tx_ready_i,
            tx_data_o, tx_valid_o, rx_ready_o);

        $display("=== CH01 END: OBSERVATION ONLY ===");
        $finish;
    end
endmodule

판서 포인트 · 왜 reg와 wire가 다른가?

TB가 initial 안에서 값을 대입하는 변수는 reg로 선언하고, DUT가 구동하는 출력은 wire로 연결합니다. reg는 여기서 변수 종류이지 합성된 레지스터를 의미하지 않습니다. SystemVerilog의 logic은 뒤에서 다룹니다.

05예상 출력과 타이밍 다이어그램

다음은 원본의 세 대입문과 TB의 자극 순서에서 도출한 예상 출력입니다. 실제 시뮬레이터 실행 기록이 아닙니다.

콘솔 · 예상 출력 · NOT_RUN
=== CH01 UART ECHO TESTBENCH START ===
t=10 ns rx=00 rv=0 tr=0 | tx=00 tv=0 rr=0
t=20 ns rx=41 rv=1 tr=1 | tx=41 tv=1 rr=1
t=30 ns rx=5a rv=1 tr=0 | tx=5a tv=1 rr=0
t=40 ns rx=00 rv=0 tr=1 | tx=00 tv=0 rr=1

20ns 출력의 tx=41, tv=1, rr=1은 A의 수락 조건을 보여 줍니다. 30ns에는 tx=5a, tv=1, rr=0이므로 데이터는 전달 경로에 있지만 수락되지 않습니다. 40ns에는 준비되어도 유효한 데이터가 없습니다.

파형의 시간 구간은 입력이 유지되는 기간입니다. 로그는 각 구간의 끝에서 다음 자극을 대입하기 직전에 기록하므로, 같은 시각의 GUI 커서가 다음 자극 값을 표시할 수 있습니다. #10은 TB가 관찰하기 위해 기다리는 시간이며 DUT 자체의 10ns 지연을 뜻하지 않습니다.

교수용 해석 · 콘솔 시각과 파형 시각

10ns라는 같은 시간에 관찰과 다음 자극 대입이 이어집니다. $display는 현재 initial에서 다음 대입보다 먼저 실행되지만 VCD에는 같은 시각에 갱신된 신호가 기록될 수 있습니다. 따라서 10ns 콘솔의 00과 10ns 이후 파형의 41은 모순이 아닙니다.

콘솔 필드실제 신호읽는 의미
rxrx_data_i입력 데이터 16진수
rvrx_valid_i입력 유효 여부
trtx_ready_i뒤쪽 준비 여부
txtx_data_o출력 데이터
tvtx_valid_o출력 유효 여부
rrrx_ready_o앞단에 되돌려 주는 준비 상태

20ns 로그 계산: 0x41은 4×16+1 → 65이며 ASCII(아스키, 문자 부호) A입니다. 0x5A는 5×16+10 → 90이며 Z입니다. %02h는 최소 두 자리 16진수, %b는 이진수입니다. %0d는 불필요한 선행 공백 없이 정수 시간값을 출력합니다.

기존 실제 결과는 공개 실행 로그에 보존되어 있습니다. 관찰 결과와 예측값은 일치하지만 TB 자체에는 자동 비교가 없습니다.

실제 코드의미와 역할

wire [7:0] tx_data_o;DUT 출력이 구동하는 연결 신호입니다. TB는 이를 읽습니다.
uart_echo_controller dut (...)원본 모듈의 인스턴스를 생성하며 이름 기반으로 포트를 연결합니다.

교수용 문답 · 개념을 확인하는 질문

수업 질문답변 및 설명
assign은 한 줄씩 실행되나요?아닙니다. 연속 대입은 입력 변화에 반응하는 병렬 연결입니다.
왜 #10을 쓰나요?자극을 일정 시간 유지하고 관찰 시점을 분리하기 위해서입니다. DUT에 10ns 지연 회로가 생기는 것은 아닙니다.
ready가 0이면 tx_data_o도 0인가요?아닙니다. 데이터와 valid는 그대로 전달되고 수락 조건만 불성립합니다.

이 회로가 UART 프레임을 처리하나요?아닙니다. 이미 바이트로 들어온 스트림을 연결할 뿐입니다.
