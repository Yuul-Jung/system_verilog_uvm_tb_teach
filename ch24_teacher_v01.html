00개요 · 회귀 검증은 무엇을 자동화하는가

회귀 검증(Regression, 리그레션)은 코드나 환경이 바뀐 뒤 기존 기능이 계속 정상인지 반복 확인하는 절차입니다. CI(Continuous Integration, 지속적 통합)는 이러한 검사를 변경 사항마다 실행하도록 연결합니다. 이 장에서는 기존 uart_echo_controller를 수정하지 않고 시드(Seed, 난수 재현 초기값)별 반복 시험, 오류 주입, 커버리지 기록, JSON/Markdown 보고서까지 한 흐름으로 구성합니다.

교수용 이론 · 한 번의 성공을 재현 가능한 반복 판정으로 바꾼다

회귀 검증은 변경 후 기존 기능이 유지되는지 같은 기준으로 반복 확인하는 절차입니다. CI(Continuous Integration, 지속적 통합)는 실행을 저장소 변경과 연결합니다. 자동화가 가치 있으려면 무엇을 실행했는지, 무엇이 실패했는지, 실행하지 못한 것은 무엇인지 결과에 남겨야 합니다.

그림은 Python의 시드·프로세스 관리→컴파일/실행→TB 비교→JSON/Markdown 보고 흐름입니다. 대상은 조합 UART echo 한 개입니다. 제21~22장 UVM·제23장 NPU까지 이 CI에서 함께 실행한다고 설명하지 않습니다. 원본의7절 순서와 전체 코드·두 그림을 그대로 유지합니다.

01DUT 포트·시간 계약

원본은 6포트 조합 전달기입니다. tx_data_o는 rx_data_i, tx_valid_o는 rx_valid_i, rx_ready_o는 tx_ready_i를 그대로 전달합니다. 클록·리셋·FIFO·직렬 UART 프레이밍 기능은 이 DUT에 없습니다. TB에서 #1로 조합 출력 안정화를 기다리는 것은 회로에 1ns 레지스터 지연이 있다는 뜻이 아닙니다.

포트·시간 판서 · accepted는 표본의 조건 집계다

DUT는 데이터·valid를 정방향, ready를 역방향으로 연결합니다. 클록·저장·직렬 프레임이 없습니다. 각 task의 #1은 시뮬레이터 조합 갱신을 기다리는 TB 시간이며 물리 회로의1ns 지연이나 UART 비트 시간이 아닙니다.

32회 task를0ns부터 연속 호출하므로 정상 비교는1~32ns에 수행됩니다. accepted는 valid1·ready1인 표본 수이며 실제 직렬 송신 완료 바이트 수가 아닙니다. 같은 data를 연속 제시해도 별도 표본으로 셉니다.

02시드·커버리지·재현성

의사난수 생성기 xorshift32()는 입력 시드가 같으면 항상 같은 비트열을 만듭니다. 먼저 valid/ready의 네 조합을 고정 시험으로 확인한 뒤, 8개의 고정 입력과 각 시드마다 24개의 추가 입력을 생성합니다. 따라서 시드 하나당 총 32건을 검사합니다. 시드 1, 7, 42는 서로 다른 순서를 만들어 경계 조합을 더 폭넓게 탐색합니다.

커버리지 계수입력 조건의미
cov_idlevalid=0, ready=0비활성
cov_stallvalid=1, ready=0전송 대기
cov_acceptvalid=1, ready=1전송 수락
cov_ready_idlevalid=0, ready=1준비만 된 상태

여기서 커버리지는 네 입력 상태의 방문 여부를 의미합니다. 전체 기능이나 코드 라인 커버리지 100%를 뜻하지 않습니다.

수치 판서 · 고정8개 안에 네 필수 조합이 포함된다

총 입력은 고정8개+시드별 추가24개=32개입니다. 처음 네 개의00·10·11·01 조합은 고정8개에 포함되며 별도로4개를 더하는 구성이 아닙니다. 고정 부분의 [idle,stall,accept,ready_idle] 계수는[2,2,3,1]입니다. 따라서 네 상태 방문은 이미 고정 입력으로 보장되고 난수는 순서·데이터·추가 빈도를 바꿉니다.

시드1의 결과[6,12,9,5],7의[9,7,11,5],42의[12,5,9,6]은 각각 합32입니다. 전체96표본의 합은[27,24,29,16]이며 accepted29입니다. 네 상태가 모두 나왔다는100%와256개 데이터×네 제어=1024조합의 전수 검증은 다릅니다.

xorshift32는 XOR·논리 shift의32비트 상태 계산입니다. seed1의 첫 갱신은00042021이라 data=20hex, valid1·ready0입니다. Python은 임의 정밀도 정수이므로 왼쪽 shift에 FFFFFFFF 마스크를 적용해 RTL의32비트 잘림을 재현합니다. 암호용 난수 생성기는 아닙니다.

03PASS·FAIL·NOT_RUN과 음성 시험

PASS는 컴파일·실행이 정상 종료되고 정확한 성공 마커와 커버리지 조건을 확인했을 때만 부여합니다. FAIL은 컴파일 오류, 타임아웃, 출력 불일치, 기대한 오류 미검출을 포함합니다. NOT_RUN은 시뮬레이터 또는 파일이 없어 실제 시험을 수행하지 못한 상태입니다.

+INJECT_FAULT는 원본 DUT를 건드리지 않고 9번째 관찰 데이터의 하위 비트만 반전합니다. 정상 시험과 동일한 비교기가 불일치를 검출해야 합니다. 이 음성 시험은 종료 코드가 1이고 DETECTED_INJECTED_FAULT case=9가 FATAL 진단에 출력되고 정상 PASS 마커가 없어야 검출 성공으로 인정합니다. 단순히 오류가 발생했다는 사실만으로 성공 처리하지 않습니다.

판정 계약 · 예상한 실패만 부정 시험 성공으로 센다

INJECT_FAULT는 checks8인9번째 비교에서 관찰 데이터의 bit0만 뒤집습니다. seed1이면9ns에 정상20이 관찰21로 바뀝니다. 원래 DUT 세 출력이 정상이라는 추가 조건까지 확인한 뒤 DETECTED_INJECTED_FAULT case9를 냅니다. 일반 포트 오류나 timeout으로 죽어도 부정 시험을 성공으로 처리하지 않습니다.

실행기는 현재 Icarus 경로의 exit1·전용 FATAL·정상 PASS없음을 함께 요구합니다. 앞 UVM 장처럼 fatal 종료 코드 차이를 허용하는 실행기와 정책이 다릅니다. 정상 전체 harness는 예상된 부정 검출까지 통과하면0, 실제 실패는1, 준비가 안 된 NOT_RUN은2로 반환합니다.

04전체 SystemVerilog 테스트벤치

테스트벤치는 입력·출력 비교, 네 조합의 커버리지 계수, 시드 재현성, 음성 시험을 포함합니다. 원본 RTL의 여섯 포트 이름을 그대로 사용합니다.

tb/ch24/tb_uart_regression.sv · SystemVerilog · 전체 코드
`timescale 1ns/1ps
// 제24장: 실제 uart_echo_controller 6포트의 시드 기반 반복 회귀 검증.
// 이 DUT는 클록이 없는 조합 전달기이다. #1은 출력 안정화 대기이다.
module tb_uart_regression;
    reg [7:0] rx_data_i = 0;
    reg rx_valid_i = 0;
    reg tx_ready_i = 0;
    wire rx_ready_o, tx_valid_o;
    wire [7:0] tx_data_o;

    uart_echo_controller dut (
        .rx_data_i(rx_data_i), .rx_valid_i(rx_valid_i),
        .rx_ready_o(rx_ready_o), .tx_data_o(tx_data_o),
        .tx_valid_o(tx_valid_o), .tx_ready_i(tx_ready_i)
    );

    integer seed, i, checks = 0, accepted = 0;
    integer cov_idle = 0, cov_stall = 0;
    integer cov_accept = 0, cov_ready_idle = 0;
    integer fault = 0;
    reg [31:0] prng;
    reg [7:0] next_data;
    reg next_valid, next_ready;

    // PRNG(의사난수 생성기): 같은 seed이면 같은 입력 순서를 만든다.
    function automatic [31:0] xorshift32(input [31:0] value);
        reg [31:0] x;
        begin
            x = value ^ (value << 13);
            x = x ^ (x >> 17);
            x = x ^ (x << 5);
            xorshift32 = x;
        end
    endfunction

    // 입력을 안정화한 뒤 4상태 비교로 세 출력의 전달 계약 검사.
    task automatic check_transaction(
        input [7:0] data, input valid, input ready
    );
        reg [7:0] observed_data;
        begin
            rx_data_i = data;
            rx_valid_i = valid;
            tx_ready_i = ready;
            #1;
            // (변경) 9번째 표본의 관찰값만 반전한다. 원본 DUT는 그대로 둔다.
            observed_data = tx_data_o;
            if (fault && checks == 8)
                observed_data = tx_data_o ^ 8'h01;
            // 정상/부정 시험이 같은 비교기를 통과한다.
            if (observed_data !== data || tx_valid_o !== valid ||
                rx_ready_o !== ready) begin
                if (fault && checks == 8 && tx_data_o === data &&
                    tx_valid_o === valid && rx_ready_o === ready &&
                    observed_data === (data ^ 8'h01))
                    $fatal(1, "DETECTED_INJECTED_FAULT case=9");
                $fatal(1, "FAIL PORT_CONTRACT case=%0d", checks + 1);
            end

            if (!valid && !ready) cov_idle = cov_idle + 1;
            if ( valid && !ready) cov_stall = cov_stall + 1;
            if ( valid &&  ready) cov_accept = cov_accept + 1;
            if (!valid &&  ready) cov_ready_idle = cov_ready_idle + 1;
            if (valid && ready) accepted = accepted + 1;
            checks = checks + 1;

        end
    endtask

    initial begin
        #10000;
        $fatal(1, "FAIL GLOBAL_TIMEOUT");
    end

    initial begin
        if (!$value$plusargs("SEED=%d", seed)) seed = 1;
        if ($test$plusargs("INJECT_FAULT")) fault = 1;
        prng = seed;
        if (prng == 0) prng = 32'h6d2b79f5;

        // 4가지 valid/ready 조합을 반드시 방문한다.
        check_transaction(8'h00, 0, 0);
        check_transaction(8'h41, 1, 0);
        check_transaction(8'h41, 1, 1);
        check_transaction(8'h5a, 0, 1);
        check_transaction(8'hff, 1, 1);
        check_transaction(8'h00, 1, 0);
        check_transaction(8'h0a, 1, 1);
        check_transaction(8'h55, 0, 0);

        // seed별로 24개의 재현 가능한 조합을 추가한다.
        for (i = 0; i < 24; i = i + 1) begin
            prng = xorshift32(prng);
            next_data = prng[15:8];
            next_valid = prng[0];
            next_ready = prng[1];
            check_transaction(next_data, next_valid, next_ready);
        end

        if (checks != 32 || cov_idle == 0 || cov_stall == 0 ||
            cov_accept == 0 || cov_ready_idle == 0 ||
            cov_idle + cov_stall + cov_accept + cov_ready_idle != checks ||
            accepted != cov_accept)
            $fatal(1, "FAIL COVERAGE checks=%0d", checks);
        $display("COVERAGE seed=%0d idle=%0d stall=%0d accept=%0d ready_idle=%0d",
                 seed, cov_idle, cov_stall, cov_accept, cov_ready_idle);
        $display("PASS CH24 seed=%0d checks=%0d accepted=%0d", seed, checks, accepted);
        $finish;
    end
endmodule

코드 풀이 — 핵심 구문

$value$plusargs("SEED=%d", seed)는 실행 시드를 읽습니다. xorshift32()는 그 시드를 32비트 상태로 갱신합니다. check_transaction()은 입력을 넣고 #1 뒤 세 출력을 !==로 비교합니다. 네 커버리지 계수의 합은 32가 되어야 하며, 하나라도 0이면 시험이 실패합니다.

전체 TB · 재현할 수 있는 입력과 비교기 자기 점검

시드를 기록하면 같은 xorshift 상태와 입력 순서를 다시 만들 수 있습니다. 다만 코드·DUT·도구가 달라지면 시드만으로 동일 실행을 보장하지 못하므로 실행기는 실제 파일 Blob과 도구 버전도 남깁니다. TB는 seed0을 대체값으로 바꾸지만 Python 정상 인터페이스는1~2147483647만 허용합니다.

정상·부정은 같은 !== 비교 조건을 통과합니다. 주입 여부만 보고 곧바로 성공 문구를 출력하지 않아 비교기가 실제 불일치를 찾는지 점검합니다. 정상 자극은0/1 데이터·제어라4상태 비교를 사용한다는 사실만으로 모든 X/Z 입력을 시험한 것은 아닙니다.

#!/usr/bin/env python3
"""제24장 회귀 실행기: 시드·음성 시험·JSON/Markdown 보고서 생성."""
import argparse
import datetime as dt
import hashlib
import json
import pathlib
import re
import shutil
import subprocess
import sys
import tempfile

ROOT = pathlib.Path(__file__).resolve().parents[1]
DUT = ROOT / "reference_rtl" / "uart_echo_controller.v"
TB = ROOT / "tb" / "ch24" / "tb_uart_regression.sv"
BUILD = ROOT / ".build" / "ch24"
EXPECTED_BLOB = "28160c34522e47fbd961466651598da063bc74ae"


def blob_sha(path):
    """실제 파일 바이트에서 Git blob SHA-1을 계산한다."""
    data = path.read_bytes()
    return hashlib.sha1(f"blob {len(data)}\0".encode() + data).hexdigest()


def expected_coverage(seed):
    """8개 고정 입력과 24개 PRNG 입력의 독립 Python 계산."""
    counts = [2, 2, 3, 1]  # idle, stall, accept, ready_idle
    x = seed or 0x6d2b79f5
    for _ in range(24):
        x ^= (x << 13) & 0xffffffff
        x ^= x >> 17
        x ^= (x << 5) & 0xffffffff
        counts[(0, 1, 3, 2)[x & 3]] += 1
    return counts


def execute(command, timeout=30):
    """종료 코드와 stdout/stderr를 합쳐 재현 가능한 로그로 반환한다."""
    try:
        p = subprocess.run(
            command, cwd=BUILD, capture_output=True,
            text=True, timeout=timeout, check=False
        )
        return p.returncode, p.stdout + p.stderr
    except subprocess.TimeoutExpired as exc:
        return 124, "TIMEOUT: " + str(exc)
    except OSError as exc:
        return 125, "EXEC_ERROR: " + str(exc)


def main():
    global BUILD
    parser = argparse.ArgumentParser(description="UART 회귀 검증 보고서")
    parser.add_argument("--seeds", default="1,7,42",
                        help="쉼표로 구분한 정수 시드 목록")
    args = parser.parse_args()
    try:
        seeds = [int(s) for s in args.seeds.split(",")]
        if not seeds or len(seeds) != len(set(seeds)):
            raise ValueError("중복 또는 빈 시드")
        if any(not 1 <= s <= 2147483647 for s in seeds):
            raise ValueError("시드는 1~2147483647 범위")
    except ValueError as exc:
        parser.error(str(exc))

    BUILD.mkdir(parents=True, exist_ok=True)
    # (변경) 실행마다 새 폴더를 만들어 과거 로그 혼입 방지.
    BUILD = pathlib.Path(tempfile.mkdtemp(prefix="run_", dir=BUILD))
    result = {
        "chapter": 24,
        "timestamp_utc": dt.datetime.now(dt.timezone.utc).isoformat(),
        "dut_path": "reference_rtl/uart_echo_controller.v",
        "dut_blob_sha": blob_sha(DUT) if DUT.is_file() else None,
        "expected_dut_blob_sha": EXPECTED_BLOB,
        "tb_blob_sha": blob_sha(TB) if TB.is_file() else None,
        "simulator": "Icarus Verilog",
        "seeds": seeds,
        "cases": [],
        "status": "NOT_RUN",
    }
    available = bool(shutil.which("iverilog") and shutil.which("vvp"))
    if DUT.is_file() and result["dut_blob_sha"] != EXPECTED_BLOB:
        result["status"] = "FAIL"
        result["reason"] = "원본 DUT SHA 불일치"
    elif not DUT.is_file() or not TB.is_file() or not available:
        reason = ("RTL/TB 파일 없음" if not DUT.is_file() or not TB.is_file()
                  else "iverilog 또는 vvp 미설치")
        result["reason"] = reason
    else:
        version_code, version_text = execute(["iverilog", "-V"])
        result["simulator_version"] = version_text.splitlines()[0] if version_text else ""
        code, log = execute([
            "iverilog", "-g2012", "-s", "tb_uart_regression",
            "-o", "sim", str(DUT), str(TB)
        ])
        (BUILD / "compile.log").write_text(log, encoding="utf-8")
        if code != 0:
            result["status"] = "FAIL"
            result["reason"] = "컴파일 실패"
        else:
            for seed in seeds:
                code, log = execute(["vvp", "sim", f"+SEED={seed}"])
                (BUILD / f"seed_{seed}.log").write_text(log, encoding="utf-8")
                match = re.search(
                    rf"^PASS CH24 seed={seed} checks=32 accepted=([0-9]+)$",
                    log, re.MULTILINE
                )
                coverage = re.search(
                    rf"^COVERAGE seed={seed} idle=([0-9]+) stall=([0-9]+) "
                    rf"accept=([0-9]+) ready_idle=([0-9]+)$", log, re.MULTILINE
                )
                ok = (code == 0 and match is not None and coverage is not None
                      and all(int(v) > 0 for v in coverage.groups())
                      and sum(map(int, coverage.groups())) == 32
                      and list(map(int, coverage.groups())) == expected_coverage(seed)
                      and int(match.group(1)) == int(coverage.group(3))
                      and not re.search(r"(?m)^(?:FATAL:|FAIL )", log))
                result["cases"].append({
                    "name": f"seed_{seed}", "status": "PASS" if ok else "FAIL",
                    "exit_code": code,
                    "accepted": int(match.group(1)) if match else None,
                    "coverage": list(map(int, coverage.groups())) if coverage else None,
                    "expected_coverage": expected_coverage(seed),
                })
            code, log = execute(["vvp", "sim", "+SEED=1", "+INJECT_FAULT"])
            (BUILD / "negative.log").write_text(log, encoding="utf-8")
            detected = (code == 1 and re.search(
                r"(?m)^FATAL: [^\n]*DETECTED_INJECTED_FAULT case=9\s*$", log
            ) is not None and "PASS CH24" not in log)
            result["cases"].append({
                "name": "negative_injection",
                "status": "PASS" if detected else "FAIL",
                "exit_code": code,
                "expected": "비정상 종료 및 지정된 오류 마커",
            })
            result["status"] = ("PASS" if all(
                item["status"] == "PASS" for item in result["cases"]
            ) else "FAIL")

    (BUILD / "report.json").write_text(
        json.dumps(result, ensure_ascii=False, indent=2) + "\n", encoding="utf-8"
    )
    lines = [
        "# 제24장 회귀 검증 보고서", "",
        f"- 실행 UTC: {result['timestamp_utc']}",
        f"- 상태: **{result['status']}**",
        f"- DUT Blob SHA: {result['dut_blob_sha']}",
        f"- Expected DUT Blob SHA: {EXPECTED_BLOB}",
        f"- TB Blob SHA: {result['tb_blob_sha']}",
        f"- 시뮬레이터: {result['simulator']}",
        f"- 버전: {result.get('simulator_version', '미확인')}",
        f"- 사유: {result.get('reason', '없음')}", "",
        "| 시험 | 상태 | 종료 코드 |",
        "|---|---|---|",
    ]
    for item in result["cases"]:
        lines.append(f"| {item['name']} | {item['status']} | {item['exit_code']} |")
    (BUILD / "report.md").write_text("\n".join(lines) + "\n", encoding="utf-8")
    print(f"CH24 REGRESSION {result['status']}: {BUILD / 'report.json'}")
    return {"PASS": 0, "FAIL": 1, "NOT_RUN": 2}[result["status"]]


if __name__ == "__main__":
    sys.exit(main())

원본 파일이 존재하면서 SHA가 다르면 FAIL, 파일 자체가 없거나 실행 도구가 없으면 NOT_RUN입니다. 시드별 시험의 결과와 오류 주입 검출 결과를 함께 집계합니다.

실행기 코드 풀이

blob_sha()는 실제 파일에서 Git Blob SHA를 계산해 원본 변경을 검출합니다. expected_coverage()는 독립 Python 계산으로 네 계수를 예측합니다. 종료 코드, 정확한 마커, 합계 32, 수락 개수와 독립 계산이 모두 일치해야 정상 시험이 PASS입니다.

GitHub Actions(깃허브 액션스, 저장소 자동 작업)는 해당 파일 변경 또는 수동 실행 때 Icarus Verilog를 설치하고 같은 스크립트를 실행하도록 구성합니다. 실패해도 로그를 아티팩트로 보존합니다. CI 설정 파일을 작성한 것과 GitHub에서 실제 실행 성공한 것은 별개입니다.

실행기·그림 읽기 · 입력 검증부터 보고서까지 책임을 나눈다

흐름도에서 존재하는 DUT의 SHA 불일치는 FAIL, 파일·도구 부재는 NOT_RUN입니다. 준비 후 컴파일·정상 시드·부정 검출이 모두 성공해야 PASS입니다. execute는 timeout을124, 실행 OS 오류를125로 구별하고 새 run 폴더로 과거 PASS 로그 혼입을 피합니다.

blob_sha는 원시 파일 SHA256이 아닙니다. Git 방식의 ‘blob 길이 + NUL + 바이트’에 대한 SHA-1이며 EXPECTED_BLOB과 실제 DUT 내용을 비교합니다. TB Blob은 기록하지만 고정 기대값과 비교하지 않습니다. 문서가 실제 코드보다 강한 무결성 보장을 주장하지 않게 구분합니다.

expected_coverage의 인덱스는 low2bits=00→idle,01→stall,10→ready_idle,11→accept입니다. 네 계수 양수·합32만으로는 분포 오기록을 못 찾으므로 Python 독립 계산과도 일치해야 합니다. JSON과 Markdown은 같은 result에서 생성하며 서로 독립 검증기는 아닙니다.

워크플로는 지정 경로 push 또는 수동 실행으로 동작하도록 작성되어 있고 실패해도 always 조건으로 .build 보고서를 올립니다. YAML을 제시한 사실, 로컬 회귀 PASS, 원격 Actions 실제 성공은 각각 다른 근거가 필요합니다. 교수용 저장소에 이 원본 RTL 회귀를 새로 설치·실행한 것으로 표시하지 않습니다.
