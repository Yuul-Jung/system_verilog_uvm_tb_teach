## 2. 실제 발행본에 대한 독립 반례

독립 JS 비교기로 각 최신 페이지에 원본 pre 내용 변경, SVG 삭제, section 삭제를 메모리상 적용하고 24×3=72건을 모두 검출했다. 기존 Python 검증기 전체 실행을 재수행했다는 뜻은 아니다.

## 3. 기존 검증기의 반례 시험

고정 커밋 `scripts/validate_teacher.py`의 Text, text, validate_page 및 main 로직을 임시 Python 시험 환경에 옮겨 실행했다. 정상 합성 fixture는 통과했고 원본 코드 변경/SVG 삭제/절 삭제 세 반례는 거절되었다. 다음 아홉 반례는 거절되지 않았다.

| 반례 | 실제 결과 |
|---|---|
| 모든 teach-note를 빈 div로 변경 | errors=[] |
| teach-fragment의 실제 코드 변경 | errors=[] |
| 해설 행 번호를 범위 밖으로 변경 | errors=[] |
| 원본 증거 URL을 다른 URL로 변경 | errors=[] |
| pre에 display:none 적용 | errors=[] |
| 동일 보충 설명 중복 | errors=[] |
| 기술적으로 거짓인 보충 문장 | errors=[] |
| --chapter 99로 검사 대상 없음 | exit 0 |
| planned_chapters 24개, chapters 빈 목록 | exit 0 |

실제 교재에서 위 훼손이 발견된 것이 아니라, 검증기 자체의 보호 범위가 불충분하다는 반례다. 임의 자연어의 진위를 자동으로 보증할 수 없으므로 해설 원문 해시/변경 비교와 기술 검토를 분리해야 한다.

## 5. 승인 조건 및 미검증 범위

- 원본 보존, 실제 코드 인용, 파일 버전/목차: PASS.

- 새 6폭 브라우저·공개 Pages HTTP/해시: NOT_RUN. 현재 환경에서 공개 URL 접근 및 DNS 해석이 실패하여 사이트 자체 장애라고 단정하지 않는다.
