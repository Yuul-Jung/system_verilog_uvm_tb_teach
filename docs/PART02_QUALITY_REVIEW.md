| 장 | 핵심 역할 | 혼동을 방지한 내용 |

| 06 | 여러 값의 순서 | 배열 [3-i]→[i], 입력 기반 기대 큐 소비, package 선행 분석 |

네 장 모두 같은 uart_echo_controller를 사용한다. DUT에는 클록·리셋·FIFO·객체가 없다. 구조체·배열·큐·객체는 TB의 표현이며, interface 신호에 접근하는 시점이나 객체 필드를 DUT 입력에 대입하는 지점을 명확히 설명했다.

주요 수치 검토: CH05 packed 값 `(65<<2)|3=263`, CH06은 필드 순서가 달라 `(1<<9)|(1<<8)|65=833`이다. CH05는 4사례+2타입=6검사, CH06은 6신호 사례+4데이터+1잔량=11검사이다. CH07은 5ns 구동과 15ns 첫 관찰을 구별하며 45ns에 끝난다. CH08의 문자 공간 126-32+1=95, 부모 95×2×2=380은 가능한 조합 수이고 실제 무작위화는 두 번이다. 모든 수치는 실제 구문과 보존 로그의 계약을 근거로 검토했다.

CH05의 data→valid→ready와 CH06의 valid→ready→data 필드 순서 차이를 명시했다. CH07~08의 원본 Verilator 실행을 X/Z 보존 실측으로 과장하지 않았다. 생성 성공, 신호 비교 성공, 표본·사례 수와 기능 커버리지를 구분했다. 예상·설명용 반례와 기존 실제 로그는 구별하고 새 RTL_SIM은 NOT_RUN이다.
